# Packaging preserves committed binaries

## Scope

Implements Unit 2 of `committed-binary-distribution`. Establish
`plugin/bin/<goos>-<goarch>/peeragent` as the single committed-binary location and
make the packaging flow respect it.

- **`scripts/package-plugin.sh`**: stop `rm -rf "$PLUGIN"`. Regenerate only the
  curated parts (`.claude-plugin`, `.codex-plugin`, `skills`, and the
  `plugin/bin/peeragent` shim), leaving the `plugin/bin/<target>/` binary subdirs
  intact (owned by CI). See feature body Unit 2.
- **Seed initial binaries**: build the four targets once and commit them, so the
  artifact is self-contained before CI's first run:
  `CGO_ENABLED=0 GOOS=<os> GOARCH=<arch> go build -trimpath -ldflags="-s -w" -o plugin/bin/<target>/peeragent ./cmd/peeragent`.
- **`scripts/release.sh`**: change the `gh release` note from "Marketplace installs
  can fetch these assets on first use." to a manual-install description.
- **`scripts/bump.sh`**: keep it source-only (no binary build); switch the explicit
  `plugin/*.json` adds to `git add plugin` so the regenerated curated tree is staged
  without disturbing committed binaries.

## Acceptance Criteria

- [ ] After `scripts/package-plugin.sh`, all four `plugin/bin/<target>/peeragent`
      remain present and executable.
- [ ] Initial four committed binaries are tracked by git.
- [ ] `plugin/bin/peeragent` shim is regenerated by packaging.
- [ ] `scripts/release.sh` note no longer claims first-use download.
- [ ] `scripts/bump.sh` does not build binaries and stages the curated tree.

## Notes

Seed-build flags must match the CI workflow exactly so CI's first refresh produces no
spurious diff.

## Implementation notes

### What was done

1. **`scripts/package-plugin.sh`**: Replaced `rm -rf "$PLUGIN"` with targeted
   removals that leave `plugin/bin/<target>/` subdirs intact. The new sequence
   removes only `.claude-plugin`, `.codex-plugin`, `skills`, and the shim
   `plugin/bin/peeragent`, then recreates the curated dirs. The platform binary
   subdirs are not touched.

2. **Seeded four committed binaries** with `CGO_ENABLED=0 -trimpath -ldflags="-s -w"`,
   matching the CI build flags exactly:
   - `plugin/bin/linux-amd64/peeragent`:  2 617 506 bytes
   - `plugin/bin/linux-arm64/peeragent`:  2 556 066 bytes
   - `plugin/bin/darwin-amd64/peeragent`: 2 584 720 bytes
   - `plugin/bin/darwin-arm64/peeragent`: 2 431 618 bytes

3. **Ran `scripts/package-plugin.sh`** after seeding. Confirmed all four
   `plugin/bin/<target>/peeragent` remained present and executable.

4. **`scripts/release.sh`**: Changed `gh release create` note text from
   "Release binaries for peeragent $tag. Marketplace installs can fetch these
   assets on first use." to "Prebuilt peeragent binaries for $tag. Use these
   for manual install on platforms without a committed plugin binary."

5. **`scripts/bump.sh`**: Replaced the explicit
   `plugin/.claude-plugin/plugin.json` / `plugin/.codex-plugin/plugin.json`
   adds with `git add plugin` so the full regenerated curated tree is staged.
   No binary-building was added.
